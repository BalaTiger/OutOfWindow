# Out of Window — 虚拟窗景 Demo

一个由本地时间、太阳位置与实时天气驱动的 Electron 桌面窗景原型。Demo 使用 Three.js 实时 3D 渲染；“都市”由 Poly Haven PBR 街区与 Helsinki 远景组成，“后巷”使用 ORCA Bistro 街景，Poly Haven 扫描地形负责自然场景细节。

2026-09-08 的渲染诊断、已落实修正、截图和后续优先级见 [写实渲染研究](RENDERING_RESEARCH.md)。当前仍为原型，尤其自然场景的地形衔接、布景和材质完整性还需要重做。

新加坡上午时段、墙面法线及都市/后巷风雨响应的修正和录像见 [天气渲染记录](WEATHER_RENDERING_FIXES.md)。

后续按生成的 2D 写实参考改进了积水、湿布、可见窗蓬动画、湿叶和水花分布，画面对照与录像见 [后巷写实参考与实际改进](docs/alley-photoreal/COMPARISON.md)。

启动时会显示预加载进度：五个场景的 GLTF、共享材质和雨景着色器在首屏阶段完成解码与预热，切换场景不再启动新的资源请求。

## 运行

最简单的方式是双击项目根目录中的 `打开Demo.cmd`。

也可以在 PowerShell 中运行：

```powershell
npm install
npm run demo
```

`npm run demo` 直接打开已经构建的桌面 Demo；修改代码后使用 `npm run rebuild-demo` 重新构建。

开发预览：

```powershell
npm run dev
```

## 当前 Demo

- 都市、后巷、村庄、山林、海滨五种独立窗景；
- 后巷保留约 283 万三角面的 NVIDIA ORCA Bistro 巴黎街景与原街内机位；
- 都市复用原机位看不到的 Poly Haven CC0 公寓/工业 PBR 模块与 Helsinki CC BY 4.0 远景，形成开阔街区，保留沿街示意车流；
- 公寓按实际 3 m 模块尺寸闭合四面立面及屋顶，重复模块实例化，部分玻璃随夜晚发光；
- ambientCG CC0 PBR 道路、停车带、自行车道、人行道、车道线与斑马线组成可辨识的街道功能区；
- 平面反射海面、动态法线与岸边泡沫，独立 PBR 溪流、植被风摆和云层移动；
- 晴、雨、雪、雾天气预览与实时天气模式；
- 当地日期、时区与太阳高度共同决定时段；上午不再误标为清晨；
- 都市与后巷地表逐渐湿润、形成积水与涟漪，露天地面产生落雨水花；雨停后逐渐排水与干燥；
- 后巷窗蓬和植物响应风速、风向、阵风与落雨冲击，墙体错误的平滑法线已修复；
- 经纬度、日期、当地时间驱动太阳高度、方位、色温和光照强度；
- 后巷采用原世界坐标高度 23 m（路面以上约 16 m）的街内固定视角；都市使用独立 26 m 高度视角，两者各自配置太阳目标与环境捕获位置；
- IP 城市级粗定位 + Open-Meteo 实时天气；
- 固定摄影机构图、可折叠控制面板、程序化环境声；
- 透明无边框桌面挂件、系统托盘、鼠标穿透与精简显示模式；
- 实体窗框、窗台与玻璃反光层，景色明确位于窗户内部；
- Poly Haven CC0 高密度草丛、山体、苔藓岩石、海岸线、沙岩、悬崖与位移 PBR 地表；
- Rayleigh/Mie 解析天空、动态二维云层和大气雾，天空不使用静态远景图；
- 由实时天空、云量和天气生成线性 HDR 环境贴图，PMREM 同时提供漫反射和镜面反射，避免重复叠加球谐光；
- 五个场景各自按需载入，共用资源只解码一次；启动都市时不加载 Bistro，反复切换复用已加载模型，时间、天气和画质设置保持连续；
- `MeshPhysicalMaterial`、PMREM 动态反射、AgX 色调映射、复用深度的 GTAO 接触阴影及 FXAA；
- 节能、均衡、精细三档画质，调节像素倍率和接触阴影质量；
- 积水建筑反射按画质限频捕获，节能档关闭额外反射捕获；
- GLB 内嵌贴图正常加载、栏杆镂空保留、玻璃/金属参数校正和近处夜间路灯；
- 网络失败时自动使用上海演示数据。

## 数据与隐私

IP 定位只能提供城市/区域级近似位置，不等于用户的物理地址，更不能定位门牌。Demo 不保存 IP、坐标或天气记录；坐标仅在当前进程中用于天气与太阳计算。

当前使用：

- [ipwho.is](https://ipwhois.io/documentation) 获取免密钥城市级坐标；
- [Open-Meteo](https://open-meteo.com/en/docs) 获取当前天气。

生产版应增加首次启动授权、服务隐私政策、请求缓存、API 配额监控，以及手动城市选择。

## 产品化路线

1. 按 `src/scene-pack.js` 的统一规则继续扩充同系列 glTF 场景包，增加 LOD、实例化植被和对象级 AO。
2. 在已接入解析天空、GTAO 和基础湿润材质的基础上，验证局部间接光、CSM、体积云和局部反射，按实测成本逐项启用。
3. 引入季节、空气质量、月相与能见度数据；天气在 10–20 分钟内平滑过渡。
4. 增加桌面置底、鼠标穿透、多显示器、开机启动、托盘菜单和帧率/功耗档。
5. 场景包下载与校验，基础程序保持轻量，资源按需安装。

## 3D 免费资产策略

生产阶段优先筛选 CC0 / CC BY 且可追溯来源的写实资源：NVIDIA ORCA（完整高密度场景）、Poly Haven（摄影测量模型与 PBR 材质）和 ambientCG（PBR 材质）。低模资源只允许用于不可见的开发占位，不进入交付画面。每个第三方资产都应在 `THIRD_PARTY_ASSETS.md` 登记来源、作者、许可证、版本和修改记录。

## Demo 限制

- 后巷运行时已切换到 768 px 安全 Bistro 包；该包实际带入颜色与法线贴图，roughness/AO 由雨景 shader 的湿润、微法线和积水反射层补足，仍受缺失 ORM 通道和简化几何限制；都市的重复立面、示意车辆、简化道路和烘焙远景也还需要美术细化。
- 三个自然场景已载入扫描模型，但仍存在地形直边、扫描边界和尺度/摆放问题；加载成功不代表写实画质验收通过。
- IP 定位在 VPN、企业网络和移动网络下可能偏离实际城市。
- 环境声是无素材的程序化噪声占位，正式版应换成可追溯授权的分层声景。

## 渲染回归

先运行 `npm run dev`，在另一个终端运行 `npm run audit:render`。离屏 Electron 会固定上海坐标、日期、时间与天气，并将截图和帧时间写入 `.runtime/render-audit/`。它使用独立测试配置目录，不访问外部天气服务。

PowerShell 扩展检查：

```powershell
$env:AUDIT_VERIFY = '1'
$env:AUDIT_CASES = '[{"name":"city","scene":"city","hour":12,"weather":"clear"},{"name":"alley","scene":"alley","hour":12,"weather":"clear"},{"name":"night","scene":"alley","hour":23,"weather":"clear"}]'
npm run audit:render
```

构建版资源加载检查可在 `npm run build` 后设置 `$env:AUDIT_PRODUCTION = '1'` 再运行；此模式不需要开发服务器。切回开发检查前移除该环境变量。离屏帧率不等同于真实桌面持续运行的 GPU 功耗测试。

- 都市场景 2D 对照与改进记录：docs/city-photoreal/COMPARISON.md（含高清参考图、差异项与验证结果）。
