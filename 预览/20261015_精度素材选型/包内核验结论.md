# London / Atlanta 实际包内核验（2026-10-15）

## 最终推荐

**London用于广场/入口实体节点，Atlanta GLB用于中景办公楼立面组件来源；不推荐把任一整栋直接替换City27。** London不是整栋深幕墙升级捷径，Atlanta也不是带可移植视差shader的完整室内。两者均已有可用真实模型，不再停留于网站预览推测。此结论是静态技术适配结论，不等于固定窗景视觉验收。

用户提供London GLB31,487,888B，Atlanta GLB24,449,112B和原始ZIP99,846,957B；根目录原件保留，独立副本与SHA256见package-intake.json。London没有FBX不构成阻塞。Atlanta ZIP中包含56,471,945B的RAR，已安全列目录、检查路径/链接后解压，取得Blend4,501,308B、FBX45,210,844B、OBJ及完整分目录贴图。未执行源代码，打开Blend显式use_scripts=False，嵌入文本列表为空。

## London：哪些是真几何、哪些不是

实际对象按材质区域分开，可直接选择，不是全楼一张平面：

- `Object_60 / rails`：25,476三角形，位置焊接后46个连通部分，有立柱、管件和连接件的实体尺寸；常见立柱约0.06×0.03×0.9m。不是栏杆照片。注意46个连通部分不等于46个完整独立模块，完整长栏段仍需选择对应几何。
- `Object_68 / stairs_front`：2,704三角形，焊接后4个实体台阶组，尺寸分别约5.83×1.39×0.48、6.03×1.36×0.46、3.23×0.83×0.45、3.44×0.66×0.40m。可单独提取做已有台阶节点样板，但不能搬入其前院规划。
- `Object_88 / lower_detail_door`：3,666三角形，门主体约1.19m宽、0.20m深、3.43m高，另有把手部件。入口细节是真几何。
- `Object_10/12/14`是左/中/右矮墙或屏障组；`Object_56 / lower_detail`有47个焊接连通部分，并含较厚入口构造；不把它们当已整理好的标准化套件。
- **上层主体不能误判**：`Object_30 / building_upper_mid`整个正立面约14.640×0.0344×19.785m，只有782三角形；对应玻璃`Object_82`厚度为0。即主体正立面大部分窗口效果仍依赖薄面/纹理，不是逐窗深洞和高精框架。其他侧面局部有厚度，也不能据此把全楼称为深幕墙。
- 相比当前中景的平面色块，它能改善材质与入口节点；但若目标是前景级幕墙几何精度，整栋导入仍不足。**推荐只拆栏杆/台阶/门等节点，不为薄立面整栋负担大量贴图。**

## Atlanta：真实体块、玻璃层与“视差室内”

- 实际有12个独立网格：主体`Cube.002_Material_0`18,924三角形，玻璃、Windows、Blinds、大堂玻璃、烘焙大堂、灯、Trimsheet及`Parralax Mapping`层分别独立。能按材质层拆取，但不是每层/每窗已整理成标准模块。
- 外层玻璃和Windows许多组件本质是零厚度面（典型尺寸17.73×0×4.59m）；不能把每扇玻璃都叫厚实体窗。
- `Cube.012_Parralax Mapping_0`4,656三角形，位置焊接后352个连通部分；常见室内盒组件约17.73×4.58×4.59m或转向对应尺寸，说明**存在真实盒式退进几何**。盒内物件主要在贴图中，不是完整建模办公室。
- **没有可移植的视差shader**：GLB材质仅Principled、图像等常规节点；原始Blend中同名材质也只有Output/Principled/图像节点，没有相机向量、视差映射节点组或相应计算网络。因此不能承诺转换为UE后自动出现平台展示中的特殊视差。
- 原Blend玻璃/窗户含Transparent、Mix Shader、Light Path等Blender材质逻辑；GLB/FBX转换为标准PBR后不完全等价。FBX导入缺图0，但部分玻璃材质丢失图像连接；GLB具有KHR_materials_specular、emissive_strength、clearcoat扩展，后续仍需核验目标引擎支持。
- 原Blend29个图像数据块中5个缺失：`Interiors/Interior Mapping.png`、`Interior Mapping Emmisive.png`及Lobby_Interior下3个`Slab Marble`图。它们不在RAR或外层ZIP中，未伪造替代。GLB已烘焙/打包的23图均正常；本轮没有证明上述旧缺图全部属于活动输出路径，不把它们等同于GLB渲染必坏。
- 建议以**GLB框架/玻璃/盒式退进层为提取来源**，保留原中景体量后适配可见立面；不要把原Blend当即插即用的“高级视差材质包”。

## UV、法线与拆分检查

已对重点门、栏杆、台阶、上层墙/玻璃、Atlanta窗户及室内盒层按位置1e-5m容差焊接统计，避免把glTF因UV/硬法线拆开的顶点误当独立模块。重点对象存在UV，非有限UV坐标0，零长度顶点法线0。London重点对象1套UV；Atlanta Windows3套、Parralax2套，其余重点玻璃1套。数据可用，但尚未渲染验证所有法线方向、透光/反射或每处接缝；不可把静态检查写成像素验收。

## 纹理与内存预算

- London全部图像RGBA8解码约**784MiB**，含完整mipmap约1.02GiB；若按RGBA32F粗上界则约3.06GiB，仅用于说明浮点解码风险，不冒充真实进程占用。整楼纹理成本高。
- 只取London `rails + stairs_front + lower_detail_door`实际关联**2张2K图**，RGBA8约**32MiB**，明显适合局部节点样板。
- Atlanta GLB全部图像RGBA8约**155.625MiB**，含mipmap约207.5MiB；RGBA32F粗上界约622.5MiB。整楼几何/纹理成本低于London，但体量比例不符现有楼。
- 静态导入两GLB本轮监控峰值1,311,424,512B（约1.22GiB），5.64秒；原Blend/FBX核查峰值412,442,624B，2.61秒。没有渲染，不把静态导入峰值当未来场景渲染预算保证。后续小样仍须单进程两线程、2.5GiB上限，先只加载选定节点。

## 与City27现有楼的具体适配

本轮实际只读检查City27：`WB06_Context_Left_Office`约16×38×70.10m、12三角形；`WB06_Context_Right_Horizontal_Slab`51×35×46.10m、12三角形；`P14_Left_L01`约29.8×38.9×92.99m、3,132三角形。当前确有可见色块楼和较粗框架来源；这些值说明可见立面组件值得升级，不授权整体替换。

Atlanta整楼约61×97×212m；若等比缩到93m高，平面约26.7×42.5m，仍与原29.8×38.9m不同。缩到46m高则又变为明显细塔。London本体约25m高且全包带宽场地，整栋拉高到70–93m会破坏层高和门窗比例。因此两者都不适合整栋硬塞、非均匀拉伸或改变已批准楼体。

**最终顺序**：先London门/台阶/栏杆小节点（真实、可拆、低纹理负担）；中景选Atlanta的主体框架及玻璃/室内盒层作局部立面素材，不依赖所谓视差shader；保留原楼顶标高和轮廓，不直接植入全栋。若必须得到逐窗细框架的近景质量，这两个包都不足以自动完成该目标，需继续找适配部件或按已核实实景参考作备用补建。
