### 几何结论

例 `79adb7c9ba530617` 的正面 U 形包边只覆盖其包围矩形约 17.6%，却被识别成完整房间。上沿约 19.1 cm，左右窄条约 17.1 / 13.7 cm。真正玻璃在包边之后约 63 cm，仍处于木窗框外轮廓以内；生成 UV 前后的逐三角顶点位置一致。现有证据支持先修正模型面分类/材质分区，不支持全窗外移或统一缩放。

当前 `window-uv-v2` 对包边及非窗面写入 `UV2.y=-1`，同时排除室内分支与旧窗发光回退；仅设置为 0 会进入旧回退。合计排除 26 组包边的 259 个三角面及另外 52 个非窗面，保留 393 个房间组。原室内后层顶点不移动，另外复制真窗片形成 66 个向外偏移 1 cm 的原生透明玻璃前层。

### Bloom 与照明的边界

均衡档对应 Scalability 2，UE 默认 BloomQuality 5、Gaussian bloom。v6 对带 `OOWWindowLookdev` 标签的后处理体积增加夜间渐变：强度 1.3、尺寸 5.5、曝光补偿 -1.15；通过 `oow.NightBloom`、`oow.NightBloomSize`、`oow.NightExposureBias` 可调。运行审计已增加最终 View 的 bloom、曝光和适应状态读回；设置值与最终读回值分别记录在验证数据中。

纹理过滤、镜头 bloom、窗台受到的真实照明是三件事。后处理 bloom 可以越过场景物体的屏幕轮廓，窗台暖光则需要场景光照响应。Epic 的 [Bloom 文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/bloom-in-unreal-engine) 说明了多尺度光晕以及强度/尺寸的分别控制；该在线文档可能指向更新引擎版本，具体实现仍以本机 5.7 源码为准。

## 当前实现与验收边界

v6 将原生 ThinTranslucent 玻璃、室内底图和 HDR 灯具高亮分开。六张图采用 Sharpen0 mip，实例 Bias 1.5、底图增益 0.8、高亮增益 8、阈值 0.32。雨篷使用原生 TwoSidedFoliage，实例透射强度 0.2 / 光学厚度 0.65；12 盏有阴影 RectLight 以每窗 `2 lm × gain`、400 cm 半径提供局部入射光，跟随同一亮灯状态和夜间渐变。

`09_19` 百叶组件采用独立双面材质实例及双面投影，修复单面片的背面遮挡，没有修改全局阴影 bias。灯光资产读回为 shadow bias 0.5、slope bias 0.5、contact shadow length 0，光追阴影沿用项目设置。源叶片仍是贴图平面，不能宣称已有真实立体叶片或条纹阴影；也没有增加可进入的室内、真实窗帘或完整室内视差。

最终资产审计为 0 失败：66 个玻璃前层、68 个室内 Actor、6 张纹理、12 盏局部灯。四例的帧间隔 P95 均约 16.7 ms，这是应用帧间隔而非 GPU timer，不代表任意场景或长期负载成绩。重建顺序、场景标签、参数来源及验证边界见 [v6 修复记录](../../Migration/window-lookdev-repair.md)。v4/v5 的旧包证据继续保留在 [夜窗历史记录](../../Migration/night-window-repair.md)，不覆盖为新版本成绩。
