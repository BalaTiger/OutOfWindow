# 后巷窗内景观重新评估（已采纳的分配依据）

以下保留针对 `window-uv-v4` / 材质 `v14` 的原始测量与分配依据，文中“当前实现”“拟议方案”描述评估时的状态。用户批准后，分配已落实为 `window-uv-v5` / 材质 `v16`、15 个实体室内与校准 cubemap IM；实际验收和安装状态见 [实施记录](window-interior-mapping.md)，不以本页历史描述判断现状。

**建议：扩大到约 15 个窗洞对应的简化 3D 配置；其余 31 个可见源窗组使用正确的 Interior Mapping。** 后者分为 17 个带室内细节的烘焙 IM 和 14 个无家具层的低细节 IM。所有可见分组都停用“完整透视室内照片直接贴后墙”的旧做法。上一轮只对四个示例窗做 3D，缺少全场景可见性排序，应按本次清单重新分配。

## 当前实现与差距

目前四个指定窗使用实体室内及独立玻璃，其余适配窗采用射线与虚拟房间盒体求交。背景方案确实具有 Interior Mapping 的求交部分，但家具与室内细节仍来自贴在后墙上的完整摄影图，尚未形成各面投影一致的室内素材管线。

- `unreal/Scripts/build_surface_materials.py:334–367`：根据窗的连续 UV、宽高、世界法线和相机方向构造局部坐标，计算后墙、侧墙、天花板或地板的最近交点。以源几何面法线复算全部 393 个窗，shader 与 CPU UV 生成的 right/up 基底最大差为 `1.57e-16` / `0`。这是 CPU 数学核对，不是 GPU 法线读回。
- 同文件 `:345–355`：相机位于窗下方时，室内射线的局部向上分量为正，向上交点被归为天花板，未发现将仰视误判为地板的符号错误。
- 同文件 `:356–362`、`:387–403`：后墙通过 `hit.xy` 采样六张完整室内照片；侧墙、顶和地面仅着纯色。照片中的地板、桌面、家具没有各自的深度，原摄影机的俯视透视被保留。2:3 裁切可以保留图片比例，不能恢复照片中缺失的空间信息。
- 同文件 `:347–348`：虚拟房间宽高为窗的 `1.24` 倍，深度仅为窗最小尺寸的 `.45` 倍，并限制在 `.35–1.35m`。盒体较浅，很多仰视射线仍先命中摄影后墙，加重了照片感。

因此，“仰视窗仍看到大量地板”的主要根因是把完整摄影图里的地板当成后墙像素，而不是求交算法把天花板与地板颠倒。单纯加深盒体、平移图片或裁掉下部内容只能缓解，不能使家具获得正确的空间关系。

## 真实窗格反例

可见的 A 窗 `2c4f36af47ee8629`，源 actor 为 `OOW_00760_paris_building_09_8`，窗尺寸为 `1.88654 × 2.74836m`，当前虚拟深度为 `0.84894m`。采用 `.runtime/ue-interior-depth/packaged-2021.json` 记录的相机位置，UE 坐标换算为米是 `(-20, -208, 23)`。

在窗 UV `(.5, .1)`，局部射线为 `(.37473, .28996, .88063)`，相对窗向上约 `18.23°`。它正确命中后墙 `face=0`，却采样 `unreal/Art/WindowInteriors/room-03.png` 的 UV `(.65442, .73363)`，正落在原图地毯上。窗 UV 改为 `(.5, .5)`，向上约 `22.02°`，仍命中后墙，对应图片 UV `(.65442, .40218)`。这是源几何及材质公式的 CPU 复算；图片选择是 CPU 估计，GPU 可能因 Nanite UV 量化在哈希边界有差异，但换成其他整张透视照片仍存在同类问题。

## 拟议的基本 Interior Mapping 素材管线

Interior Mapping 并不要求必须使用 cubemap。一张经过正确预投影的 2D room atlas 也可以表达房间各面；关键是素材的投影、捕获相机与运行时盒体映射一致，而非将任意完整室内照片直接当成后墙。

优先复用现有实体房间模板，离线生成少量室内变体，并先完成正确的基本盒体 Interior Mapping：

1. 固定房间局部坐标、代理盒体尺寸、地板/窗台高度、捕获位置和曝光。隔离窗外与玻璃，使用模板已有家具和灯光构成一致的室内内容。
2. 可选 cubemap：从约定的捕获中心离线烘焙静态 HDR，运行时以射线与盒体交点相对捕获中心的方向采样。捕获中心和盒体范围必须随素材保存，不能把反射向量直接当作室内采样方向。
3. 或选预投影 atlas：按已知相机标定与盒体形状生成房间 tile，运行时由完整交点（包括深度）映射到 tile；也可将后墙、侧墙、顶和地面展开到明确的面区域。必须验证各面边界、上下朝向、裁切和 mip 接缝。现有六张无深度的摄影图不能自动成为这样一套素材。
4. 对同一素材验证平视、仰视、俯视和斜视：仰视不应继续显示不可能可见的地板/桌面；墙面与天花板交界应随视角移动。保持烘焙曝光和运行时亮灯强度分离，避免把整张室内图提升到灯具亮度。

这种基本方案仍把家具的烘焙外观近似附着到代理盒体，无法提供实体家具的全部遮挡与视差。先验证基本 IM 已解决投影问题，再决定是否需要更复杂的深度信息；本轮不建议优先增加双深度 POM。

一手资料依据：

- [Andrew Gotow：Interior Mapping Part 2](https://andrewgotow.com/2018/09/09/interior-mapping-part-2/) 提供局部坐标射线—盒体求交与预投影 2D atlas 实现，其采样坐标明确使用交点深度。说明正确 IM 可以基于 2D atlas。
- [J Tuason：Marvel’s Spider-Man 2 Window Shader and Pipeline](https://jtuason.artstation.com/projects/XgVxQL) 说明该项目的视差室内使用 emissive cubemap 和专门烘焙管线，并将其与 RT 室内区分。
- [Epic：Scene Capture Cube](https://dev.epicgames.com/documentation/en-us/unreal-engine/1.6---scene-capture-cube?application_version=4.27) 说明 UE 的立方体捕获和 render target 能力。本项目拟议用途是离线烘焙后使用静态纹理，不是在每个窗内持续运行捕获。

## 拟议的分配与预算原则

以最终输出分辨率下的窗格屏幕尺寸、观察角度、可见时间及遮挡需求决定方案，不能只按世界距离或“亮灯/不亮灯”分配。大窗、明显仰视或斜视、家具轮廓醒目且需要真实遮挡的窗优先采用简化实体室内；中等屏幕尺寸、仍能看清室内结构的窗使用正确投影的 IM；很小或大部分被窗帘遮挡的窗可保留简单暗部、窗帘和局部亮光。具体像素阈值应由逐窗截图验证后确定。

灯光预算与几何预算分别管理。增加一个实体室内不等于必须增加一盏实时阴影灯：中远景房间可复用低模、烘焙室内照明或使用克制的自发光；实时灯与阴影只分配给确实影响可见家具或外墙的重点窗。评估几何时统计实例、三角形和 draw calls，评估灯光时另统计可见灯、阴影、GI 与 GPU 开销。

若暂不建立烘焙管线，较低成本的替代是让后墙只承载后墙与远处物件，侧墙、顶和地面使用独立平面纹理；对最明显的上层窗复用简化实体模板。这些方案也需要实景验证，不能用裁图代替空间正确性验收。

## 制作与验收边界

近景采用低模房间，参考每个配置约500–1,200三角形、2–3个材质分区，15间约7,500–18,000三角形；最近重点窗可提高预算。这是制作目标，不是已生成或测得的数量。现有4间共有20,424三角形，直接把当前每间约5,000三角形的书脊、倒角和小物件复制到15间并不合适。优先保留窗台、墙角、桌/椅/沙发大轮廓、灯具和真实遮挡。

室内灯总额仍以现有12盏为起点，重新分配4盏房内点光和8盏窗外面光的预算。只向亮灯且对可见室内或外墙有实际贡献的房间分配实时阴影灯；暗房几何不强制开灯，IM优先使用烘焙亮度。新增几何数量和实时灯数量分开核算。当前约60FPS的封顶结果不能证明有多少GPU余量。

下一轮验收必须直接检查 A、B、左近列、中央成对窗及 C/D：仰视不应看到不可能可见的大片地板，俯视应有正确地面，斜视应出现自然侧墙与家具遮挡；同一材质在仰/平/俯三个方向核对。并检查12:00、20:21、23:00雨夜与1280×820、1920×1080视口，分别记录真实GPU灯光、阴影、透明层和材质成本，不能只用总体60FPS作结论。
